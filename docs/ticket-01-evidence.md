# Ticket 01: runnable desktop foundation

Implements [issue #2](https://github.com/barnabyg/videoBrowser/issues/2), the first slice of [spec #1](https://github.com/barnabyg/videoBrowser/issues/1). The existing domain decision keeps thumbnail extraction independent of external playback.

## Selected approach

- **UI/runtime:** Electron 44.5.1, TypeScript 6.0.2, sandboxed renderer with context isolation, restricted IPC and a local Content Security Policy. Use ordinary labelled browser controls, native folder selection or an editable absolute path, and an aligned image grid. Retain this runnable foundation for later slices.
- **Thumbnail/probing engine:** pinned FFmpeg/ffprobe 9.0.2 Gyan essentials Windows x64 executables, accessed by absolute package-relative paths. Files are read; generated PNGs went under `%LOCALAPPDATA%\video-browser\thumbnails` (since issue #24, `data\thumbnails` beside the application). Probe and decode processes accept only file/pipe protocols.
- **Architecture/package:** Windows 11 x64, a preliminary zip of Electron's complete runtime, compiled app and both media tools. No installer, separately installed codecs/tools, Node.js or additional runtime setup is required by the extracted application. Development/build setup downloads dependencies once.
- **Desktop automation:** Playwright 1.63.0 Electron automation drives the real window, visible controls, extracted images and Windows shell delegation. A unique temporary extension/ProgID points to a controlled Node handler. Tests inject that extension into the actual app's extension set through the debugger; the UI and launch implementation are unchanged. No normal `.mp4` or other user association is changed. The handler records the exact source path, including spaces/non-ASCII characters. Tests delete both registry keys in `finally`.
- **Initial extension allowlist:** `.mp4`, `.m4v`, `.mkv`, `.webm`, `.mov`, `.avi`, `.wmv`, `.mpg`, `.mpeg`, `.ts`, `.mts`, `.m2ts`, `.3gp`, `.h264`. This controls listing, not a guarantee of decode or default-player coverage. A corrupt/unpreviewable source stays available for launch.
- **Redistribution review:** retain Electron's full notices and the selected tools' GPLv3 LICENSE/README. The selected build is not LGPL-only. This is a private engineering deliverable; public distribution remains out of scope and needs exact corresponding-source/build-material compliance. See [dependency review](dependencies.md) for pinned download, checksum and primary sources.

## Investigation and measurements

Environment on 2 October 2026: Windows 11 Pro 10.0.26300 (26H2, build 26300.9457), Intel Core i7-12700K, 20 logical processors, approximately 128 GiB RAM. Generated fixtures and fresh isolated application state live on the local C: SSD. The preliminary measurement includes Playwright clicking **Open folder**, folder enumeration, IPC and observation of the real grid; it excludes launch/setup and fixture generation. It is one controlled local result, not a hardware-independent guarantee. Removable-drive performance was not measured.

The matrix completed within roughly 3.2 seconds after folder selection on the observed run, including sequential decoding and automation observations; per-entry observation timestamps are cumulative and do not claim isolated extraction duration. Generated patterns are visually identifiable and portrait/landscape images fit completely; they do not establish recognisability of the user's real footage.

## Selected fallback policy

Probe duration, then try 10%, 50%, and the first frame if duration is finite and positive. If duration is unavailable/unreliable, try the first frame without seeking, then one second and five seconds. Stop after the first non-dark extracted image. A frame is provisionally dark when its 32×32 sampled mean RGB brightness is below 12/255. If all successful images are dark, retain the last image with an explanation. If none succeeds, keep a placeholder and the launch action. These thresholds are initial technical choices, not scene-recognition claims.

One shared 30-second elapsed AbortSignal budget covers probing and all attempts, excluding queue waiting. Folder changes/close cancel work. Output buffers are capped at 8 MiB. The first slice extracts sequentially; visible priority, resource scaling and deterministic timeout stress belong to subsequent tickets. No thumbnail failure prevents Windows launch delegation.

## Verification foundation

`npm.cmd run verify` runs the required seven gates in order. Tool versions/configurations and the npm lockfile are committed. Formatting is check-only; lint warnings fail; TypeScript checks both application and tests without skipped library checks; type-aware ESLint covers unawaited/misused promises and invalid async/array operations. Node tests exercise dashboard state/endpoints, concurrent ports, stage order and reporter degradation. Desktop tests cover real extraction, source bytes/modification time preservation, launch observation, matrix cases and preliminary grid timing. Packaging smoke extracts the actual zip and launches its own executable with PATH limited to Windows System32, asserting `app.isPackaged`, real thumbnail and controlled Windows launch.

Dependency verification uses npm audit with a low-severity threshold, exact-version/lockfile consistency and high-confidence source credential-pattern scanning. The scanner detects private-key headers and GitHub/npm/AWS access-key patterns; it is not a guarantee against every possible secret. There is no separate compiled native application module requiring a native analyzer. The only style exception is `@typescript-eslint/no-require-imports` for the tiny CommonJS `tests/player-observer.cjs`, justified beside the configuration and reviewed on an ESM migration. Conflicting `NO_COLOR` is removed from test-runner environments so Playwright's own color setting does not generate a Node warning. No diagnostic-warning baseline is used.

CI uses a Windows runner and the same canonical command. GitHub-hosted Windows CI itself has not yet been executed. The package has been tested on this Windows 11 host with bundled runtime/tools and a restricted PATH; a clean Windows 11 VM with no developer tooling remains a manual validation prerequisite, not a claimed result.

## Manual checks and expected outcomes

1. Extract `dist/VideoBrowser-win32-x64.zip` in a writable local application folder on Windows 11 x64. Disconnect network access and double-click `VideoBrowser.exe`. Expect the folder controls immediately, without runtime installation. For fresh-machine validation, use a clean VM without Node.js, SDKs or FFmpeg.
2. Use **Choose folder…** to select a folder containing a normal `.mp4`, preferably a familiar landscape clip and a portrait clip. Expect the exact selected path, visible filenames and progressively loaded real images; full image contents should fit without cropping. Generated matrix fixtures can be found under `.verify/media-*/sources` after verification.
3. With a real Windows default video player installed, click a thumbnail or filename. Expect the selected source to open in that player while the browser remains open at its current position. Try spaces/non-ASCII names and an unpreviewable but externally playable file. No files should appear beside source videos.
4. Use Tab to reach the folder controls and a video entry; use Enter to submit a folder or open a focused video. Expect visible focus and equivalent launch. Native folder-dialog keyboard/screen-reader behavior, display scaling and comfort with real footage require human validation; later ticket #6 extends keyboard grid navigation and size controls.
5. Remove a selected source externally, then click its entry. Expect a clear launch error with the browser still usable. Choose an empty folder and an unavailable path; expect understandable empty/error messages.

Actual default-player UX, clean-VM startup, real USB disconnection/reconnection, screen-reader behavior and real-world format diversity are not claimed as tested. Saved preferences, sorting, adjustable size, Refresh, cache reuse/eviction/clearing, viewport scheduling and 10,000-entry stress are intentionally left to their respective tickets.
